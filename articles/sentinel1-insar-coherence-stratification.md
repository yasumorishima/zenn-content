## 結論

2026年7月28日の熊本の地震について、ESA の Sentinel-1 と ASF の無料処理サービスだけで干渉解析をしました。手元に重い計算環境は要らず、費用もゼロです。

その過程で、危うく間違った結論を出しかけました。被害の指標として使った干渉性の変化を**シーン全体で平均したら、中央値が −0.024**、つまり「地震をまたいでも地表は変わっていない」と読める値だったのです。

震央からの距離で層別したら、話がまるで違いました。

| 震央からの距離 | 干渉性低下が 0.3 を超えた画素の割合 |
|---|---|
| 0–10 km | **40.3 %** |
| 30–50 km | 4.7 % |
| 120–200 km | 2.6 % |

遠方が雑音の水準（2.6〜4.7 %）で、震央近傍はその約 10 倍でした。信号は最初からあって、面積で圧倒的多数を占める遠方に薄められていただけです。

この「全体統計だと消える」現象は干渉解析に限った話ではないので、そこを中心に書きます。

## 干渉解析で何が分かるのか

合成開口レーダー（SAR）衛星は電波を地表に当てて跳ね返りを受けます。可視光のカメラと違い、雲があっても夜でも同じように撮れます。災害直後に光学衛星が雲で使えない、という事態を避けられるのが利点です。

同じ軌道から撮った 2 時期の画像を比べると、次の 2 つが得られます。

- **位相の差** → その間に地面がどれだけ動いたか。センチメートル単位で分かります
- **干渉性（コヒーレンス）** → 2 時期で地表の「電波的な見え方」がどれだけ保たれているか。0 に近いほど、その間に地表が変わったことを意味します

建物が壊れたり斜面が崩れたりすると、電波の跳ね返り方が根本的に変わるので干渉性が落ちます。これを被害の手がかりに使う、というのが今回の 2 つ目の題材です。

## データを選ぶ

まず、地震後にその上空を衛星が通っているかを調べます。ASF の検索 API は認証なしで叩けます。

```bash
curl -s "https://api.daac.asf.alaska.edu/services/search/param\
?platform=SENTINEL-1&intersectsWith=POINT(130.65%2032.60)\
&start=2026-06-20T00:00:00Z&processingLevel=SLC&output=jsonlite"
```

地震は 7/28 16:27（日本時間）でした。結果を時系列に並べると、**下降軌道（path 163）で 7/28 21:16 UTC** の取得がありました。地震のおよそ 14 時間後です。上昇軌道の 2 本にはまだ地震後の取得がなく、この時点で使えるのは下降軌道だけでした。

同じ軌道の過去の取得は 7/16、7/4 と 12 日周期で並んでいます。そこで 2 つのペアを作りました。

- **同震ペア**: 7/16 → 7/28（地震をまたぐ）
- **基準ペア**: 7/4 → 7/16（地震前だけ）

基準ペアが後で効いてきます。

:::message
この検索でハマった点です。`jq` は `|` より `,` の優先順位が高いので、`.results|length, (.results[]|...)` と書くと後半では `.` が配列のままになり `Cannot index array with string "results"` になります。`(.results|length), (.results[]|...)` と括る必要があります。
:::

## 無料で処理する

干渉解析そのものは重い処理ですが、ASF の **HyP3** というサービスが無料枠で代行してくれます。NASA Earthdata のアカウントで認証し、ジョブを投げて待つだけです。

```bash
curl -sS -X POST -H "Authorization: Bearer $EDL_TOKEN" \
  -H "Content-Type: application/json" --data @payload.json \
  https://hyp3-api.asf.alaska.edu/jobs
```

投げる前に、ペイロードに `"validate_only": true` を足すと**クレジットを消費せずに受理されるかだけ確認**できます。今回の取得は比較的新しい Sentinel-1D の画像で、処理系が対応しているか分からなかったので、これで先に確かめました。

```json
{
  "validate_only": true,
  "jobs": [
    {"job_type": "INSAR_GAMMA", "name": "coseismic",
     "job_parameters": {"granules": ["<7/16のID>", "<7/28のID>"],
       "looks": "10x2", "apply_water_mask": true}}
  ]
}
```

HTTP 200 が返り、1 ジョブ 15 クレジットと表示されました。残高は 6921 だったので、2 本で 30 使うだけです。

処理は 2 本とも成功しました。成果物のダウンロード URL は CloudFront 上にあり、**認証なしで取得できます**。つまり処理する計算機と、結果を使う計算機で認証情報を共有する必要がありません。ただし**発行から 2 週間ほどで失効**します。

:::message alert
2 つのペアは**まったく同じ処理条件で回してください**。被害の指標は 2 つの干渉性の引き算なので、解像度などを変えると差の中に処理条件の違いが混ざります。
:::

## 結果1：地面はどう動いたか

視線方向の変位は **−21.7 cm から +15.0 cm** の範囲でした。

![視線方向の地殻変動](/images/insar-kumamoto-los.png)

震央を挟んで、北東側が青（衛星から遠ざかる）、南西側が赤（近づく）と**符号が反転**しています。これは断層がずれたときに出る典型的な形です。境界の走向はこの地域の活断層の向きと一致していました。

雑音との比較も必要です。シーン全体の標準偏差は 2.7 cm で、これには大気による遅延の揺らぎも含まれます。ピークの 15〜22 cm はその 5〜8 倍なので、大気では説明できません。

## 結果2：全体統計が信号を隠した

被害の指標は、2 つの干渉性の差として作ります。

```
dcoh = 干渉性(基準ペア) − 干渉性(同震ペア)
```

正の値が「地震をまたいで干渉性が落ちた」場所です。基準ペアを引くのは、**もともと干渉性が保たれない場所を除くため**です。森林や水面は地震と関係なく常に干渉性が低いので、同震ペアだけを見ると、それらが軒並み「被害あり」に見えてしまいます。

さらに、基準ペアの干渉性が 0.3 未満の画素は判定対象から外しました。もともと見えていない場所で「変化した」とは言えないからです。

ここまで丁寧にやって出てきたのが、冒頭の **中央値 −0.024** です。素直に読めば「変化なし」です。

原因は単純で、シーンが広すぎたことでした。解析範囲は南北・東西とも 200 km を超えます。地震で変わったのは震央周辺の数十 km なので、**面積比で言えば圧倒的少数**です。全体を平均すれば消えます。

そこで、震央からの距離で層に分けて、それぞれ別に集計しました。

| 距離 | 平均 | 中央値 | 0.3 超の割合 |
|---|---|---|---|
| 0–10 km | +0.259 | +0.242 | **40.3 %** |
| 10–20 km | +0.146 | +0.121 | 22.0 % |
| 20–30 km | +0.042 | +0.021 | 7.6 % |
| 30–50 km | −0.007 | −0.016 | 4.7 % |
| 50–80 km | −0.014 | −0.017 | 4.4 % |
| 80–120 km | −0.044 | −0.047 | 3.2 % |
| 120–200 km | −0.060 | −0.056 | 2.6 % |

距離とともに単調に減っています。そして重要なのは、**遠方が雑音の実測値になっている**ことです。地震の影響が届かない 120–200 km でも 2.6 % の画素は 0.3 を超えます。これが「何もなくても出てしまう率」です。震央近傍の 40.3 % は、その約 10 倍にあたります。

雑音の水準を仮定ではなく**信号が無いはずの場所で実測する**、というのがここでの肝です。仮定していたら「0.3 超が 40 % もある、すごい」で終わるか、逆に「全体平均が negative だから駄目」で終わるかのどちらかでした。

地図にすると、こうなります。

![地表が変化した場所](/images/insar-kumamoto-damage.png)

北東から南西に伸びる、長さ 45 km ほどの帯に集中しています。遠方はほぼ空白です。そしてこの帯は、結果1 で見た変位の符号が反転する軸と重なります。**別々に作った 2 つの指標が同じ構造を指した**ので、偶然ではないと判断しました。

## この結果で言えないこと

ここは正直に書きます。

**倒壊した建物の地図ではありません。** 断層のすぐ近くでは、地表が壊れたからではなく、**変位の勾配が急すぎて位相を追いきれない**ことでも干渉性は落ちます。この 2 つは今回の材料だけでは分離できません。

**判定できたのは全体の 19.6 % だけです。** 基準ペアの干渉性 0.3 以上という条件を課すと、夏の九州は植生で広く外れます。残るのは市街地や裸地に偏ります。

**視線方向 1 成分しかありません。** 下降軌道だけなので、上下の動きと東西の動きを分けられません。上昇軌道の地震後取得が入れば分解できるので、そこは続けます。

## かかったもの

- **データ**: Sentinel-1（ESA、オープンデータ）
- **処理**: ASF HyP3 の無料枠から 30 クレジット
- **計算機**: 成果物の展開と集計だけなので、2 コアの仮想環境で足ります

有償のソフトも、大きなワークステーションも要りませんでした。

## おわりに

技術的な手順よりも、**「全体を平均したら消えた」** という一点が持ち帰る価値のある話だと思っています。対象が空間的に局在していて、観測範囲がそれより十分広いとき、全体統計は必ず信号を薄めます。そういうときは、信号が無いはずの領域で雑音の幅を測り、それと比べる。手順としては地味ですが、これをやらないと「効果なし」と書いて終わっていました。
