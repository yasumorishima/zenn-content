所属している草野球チームでは、試合ごとの成績をチームのサイトに載せています。元になるのは、試合中に書く紙のスコアブックです。これを試合のたびに手で打ち込むのは時間がかかりますし、記号の読み違いも起きます。写真から読めないかと思って試してきて、いまは Claude Code（モデルは Claude Opus 5.5）に写真を読ませ、検算してから登録しています。

ほかのチームでスコアブックをまとめている人の役に立つかもしれないと思い、手順・記号の読み方・コードを公開しました。お金を取るつもりはありません。私はスコアの付け方の専門家ではなく、自分たちのチームのスコアブックを読んできた範囲の話です。

## 全体の流れ

![スコアブックから成績を登録するまでの流れ](https://raw.githubusercontent.com/yasumorishima/baseball-scorebook-ocr-docs/main/images/blog/fig-flow.png)

1 試合でスコアブックは 2 枚あります。自軍の攻撃を書いたシートと、相手の攻撃を書いたシートです。自軍の打撃成績は自軍のシートから取ります。自軍の投手の成績（被安打・奪三振・与四死球）は、相手の打撃として相手のシートに書かれているので、そちらから取ります。

担当者がするのは、写真を貼って「○/○ の試合結果を追加」のように一言書くことと、紙では決まらない点に答えることだけです。あとは Claude Code が、読む・検算する・登録する・画面で確かめる、まで進めます。

## 1 マスは 4 つの区画に分かれ、それぞれが塁を表す

![1 マスの見方](https://raw.githubusercontent.com/yasumorishima/baseball-scorebook-ocr-docs/main/images/blog/fig-cell.png)

スコアブックは、打順の行と回の列が交わる 1 マスが 1 打席です。マスの真ん中に小さな菱形が印刷されていて、マスを 4 つに分けた区画がそれぞれの塁を表します。右下（一塁）には打者の結果、右上・左上・左下（二塁・三塁・本塁）には、その塁へ進んだ理由を書きます。

たとえば右下に `/8` とあれば中堅への安打、`6-3` なら遊撃ゴロでアウト、`B` は四球です。二塁の区画に `(5)` とあれば「5 番打者の打席のあいだに二塁へ進んだ」、`S` なら盗塁です。真ん中のローマ数字は「その回の何番目のアウトか」で、出塁したあと走者でアウトになった場合も、アウトになった本人のマスに書きます。

実物を読むと、記録者によって書き方がかなり違いました。3 つ目のアウトを Ⅳ や Ⅱ と書く人、走者のアウトで回が終わると 3 つ目を書かない人、安打だけ赤で書く人、打者が一巡して列が足りなくなると次の列へ続け、印刷された回の番号を手で振り直す人などです。33 枚を 1 マスずつ書き起こしたときに出会った書き方は、[記号の読み方](https://github.com/yasumorishima/baseball-scorebook-ocr-docs/blob/main/notation.md) にまとめました。

## 打席数は「アウト＋得点＋残塁」にぴったり一致する

![打席数は「アウト＋得点＋残塁」にぴったり一致する](https://raw.githubusercontent.com/yasumorishima/baseball-scorebook-ocr-docs/main/images/blog/fig-check.png)

1 つの打席は、最後には必ず「アウトになる」「得点する」「塁に残ったまま回が終わる」のどれか 1 つで終わります（走者のアウトや時間切れで回が終わったとき、打席の途中だった打者は打席に数えません）。出塁したあと盗塁死や封殺でアウトになっても、その打席は「アウト」で終わったと数えます。なので、回ごとにも試合全体でも、打席数はアウト・得点・残塁の和にぴったり一致します。

図は、最近の 6 回の試合（6 回裏 2 死で時間切れ）です。自軍は 28 打席で、アウト 18・得点 5・残塁 5。相手は 25 打席で、アウト 17・得点 1・残塁 7 でした。時間切れの回はアウトが 3 つに満たないので、アウトは「3 × 回数」でなく、実際に数えた数で合わせます。

確かめ方は単純で、読んだ打席を 1 つずつ「どう終わったか」に分けて数えるだけです。

```python
# 読んだ打席の一覧（回, 打順, 終わり方）。終わり方は "out" / "run" / "lob" のどれか
pas = [(1, 1, "out"), (1, 2, "out"), (1, 3, "lob"), (1, 4, "out"),
       (2, 5, "out"), (2, 6, "lob")]   # 実際は試合の全打席を並べる

from collections import Counter
for inning in sorted({p[0] for p in pas}):
    c = Counter(end for i, _, end in pas if i == inning)
    print(inning, "打席", sum(c.values()), "= アウト", c["out"], "+ 得点", c["run"], "+ 残塁", c["lob"])
```

この式と「回ごとの得点の和 ＝ 試合の得点」「投手の失点の合計 ＝ 相手の得点」などが全部合うまで読み直します。今回の試合では、5 回の 1 番打者のマスのアウトの数字が、写真全体では Ⅲ に見えました。拡大すると飾り線のついた Ⅱ でした。Ⅲ だとその回は 1 番打者で終わることになり、そのあとの 5 番打者のゴロが 4 つ目のアウトになってしまいます。記号の形で迷ったときは、こうした算術で決めています。

ほかに使っている式と、紙だけでは決まらないこと（同じ名字の選手、投手を交代した回、時間切れの回の投球回など）の決め方は、[成績をまとめる手順](https://github.com/yasumorishima/baseball-scorebook-ocr-docs/blob/main/stats-from-scorebook.md) にまとめています。

## マスごとには 9 割以上読めても、得点表が全部合うのは 33 枚中 25 枚

![マスごとには 9 割以上読めても、得点表が全部合うのは 33 枚中 25 枚](https://raw.githubusercontent.com/yasumorishima/baseball-scorebook-ocr-docs/main/images/blog/fig-accuracy.png)

検算と担当者の確認を残している理由が、この図です。写真から自動で読むツール（[baseball-scorebook-reader](https://github.com/yasumorishima/baseball-scorebook-reader)）を作り、正解を書き起こしてある 33 枚で測りました。ツールは OpenCV で格子を見つけて回の列ごとに切り出し、列ごとに Claude に「各マスに打席があるか・結果は何か・得点したか」などを聞いて、打順ごとの成績に組み立てます。

マスごとに見ると、得点したかどうかは 99%（913/923）、打席の結果は 91%（859/941）が正解と一致しました。ところが 1 枚には 30 前後の打席があるので、数マス読み違えるだけで回ごとの得点表がずれます。得点表が全部正解と合ったのは 33 枚中 25 枚でした。

同じ写真を 2 回読ませて読みが割れたマスは、61% が誤りでした（割れなかったマスの誤りは 6%）。ツールでは、割れたマスを「確認してほしいところ」として画面に出しています。

## Claude は何も渡さなくても、正解を渡した自作の画像処理と同じくらい読めた

![Claude は何も渡さなくても、正解を渡した自作の画像処理と同じくらい読めた](https://raw.githubusercontent.com/yasumorishima/baseball-scorebook-ocr-docs/main/images/blog/fig-methods.png)

Claude に読ませる前は、生成 AI を使わずに読む画像処理を、Raspberry Pi 5 の上で作っていました。白紙の用紙との差で手書きのインクだけを取り出し、区画ごとの印を見本との近さで読み、「進塁の番号は、その走者より後に打った打者の番号しかありえない」「1 つの塁に走者は 1 人で、追い越さない」といった野球の決まりと一緒に解く、という作りです。

塁の区画に書かれた印（何番打者のときに進んだかの番号など）396 か所で比べると、画像処理は何も渡さないと 71%（283/396）、正解の事実（打席・出塁・アウトの数字）を全部渡しても 92%（366/396）でした。Claude は、この比較では見本も正解も何も渡さずに読ませて、93%（370/396）でした。費用は 429 回の呼び出しで約 3.8 ドルです。

正解データは、もともと Claude の書き起こしを元に作ったものです。そのため、同じ読み違いを両方がしていると、一致が水増しされます。そこで、Claude と正解だけが一致していた 21 か所を含む 47 か所を、原本から拡大して切り出して確かめました。21 か所は全部、紙に書いてある値どおりでした。正解データの側の読み違いも 4 か所見つかりました。

画像処理のほうも、記号の読み方やソルバーの作りを読む参考になるかもしれないので、コードを公開しています（[cv/](https://github.com/yasumorishima/baseball-scorebook-reader/tree/main/cv)）。

## Claude Code でのやり方

いま試合のたびにしているのは、ツールで自動で読むのではなく、Claude Code のセッションで Claude に写真を読ませる形です。

### 手順は「スキル」に書いておく

Claude Code には、決まった作業の手順を書いておける「スキル」があります。試合結果の登録はスキルにしてあり、予定表から相手と会場を引く → 結果と回ごとの得点 → スコアブックの画像 → 打撃と投手の成績 → 検算と読み返し → 画面の確認、の順で毎回漏れなく進みます。一度、結果だけ登録して個人成績を入れずに終えたことがありました。それからは、決まった時点で自動で走る確認（フック）で、画像を上げたのに成績が入っていなければ作業を終えられないようにしています。どのチームでも使える形に直した[スキルのひな形](https://github.com/yasumorishima/baseball-scorebook-ocr-docs/blob/main/claude-code/scorebook-stats/SKILL.md)も置きました。

### 拡大して読む

1 枚全体のままだと、小さい記号を取り違えます。写真を横長に回し、打順の欄や回の列を切り出して 2〜4 倍に拡大してから読ませています。

```python
from PIL import Image

im = Image.open("sheet.jpg").rotate(-90, expand=True)   # 縦長の写真を横長に
col = im.crop((1150, 400, 1400, 1760))                   # 5 回の列だけ切り出す
col.resize((col.width * 2, col.height * 2), Image.LANCZOS).save("inning5.png")
```

### 表にして見せてから書き込む

読んだ結果は表にして担当者に見せます。同じ名字の選手のどちらか、のように紙で決まらない点だけ、Claude Code の質問の画面で選んでもらいます。確認が取れたら、結果・打撃・投手を SQL 1 本でまとめて書き込みます。書いたあとに合計を読み返して、検算の数と一致するかを確かめます。

```sql
select sum(plate_appearances) as pa, sum(at_bats) as ab, sum(hits) as h,
       sum(walks_hbp) as bb, sum(strikeouts) as k
from game_player_batting where game_id = '<登録した試合の id>';
-- pa = 28, ab = 21, h = 3, bb = 7, k = 7 … 検算の数と同じか
```

データベースの鍵は、Claude Code を動かしている PC には置いていません。自宅の小さなサーバーに置いて、そこでスクリプトを動かしています。

### 直されたことは次から守る

担当者に直された決め事は、Claude Code のメモとリポジトリの説明ファイル（CLAUDE.md）に書きます。たとえば今回、公認野球規則にならって「先発は 5 回以上投げないと勝ち投手にならない」として救援の投手に勝ちを付けたところ、「草野球なのでその下限は要らない、勝ち投手は先発」と直されました。チームの決め事として書き残し、次の試合からはそのとおりにします。

## まとめ

今回の範囲では、次のようになりました。

- 打席数は「アウト＋得点＋残塁」にぴったり一致するので、読み違いを見つける強い手がかりになる
- 自動で読むと、マスごとには 9 割以上合っても、得点表が全部合うのは 33 枚中 25 枚。検算と担当者の確認はまだ要る
- 塁の区画の印は、Claude が何も渡さずに 93% 読めて、時間をかけて作った画像処理（正解を渡して 92%）と同じくらいだった

紙のスコアブックを付けているチームは多いと思います。読み方や検算のやり方が、記録をまとめる人の手間を少しでも減らせたらうれしいです。

## 付録

**用語**

- 打席：打者が打席に立った回数。打数は、打席から四死球・犠打・犠飛などを引いたもの
- 残塁：塁に残ったまま回が終わった走者
- 区画：1 マスを縦横の点線で 4 つに分けたそれぞれ。右下＝一塁、右上＝二塁、左上＝三塁、左下＝本塁

**測った条件と注意**

- 1 種類の印刷の用紙で、1 チームの数人の記録者が書いたスコアブックです。ほかの用紙や書き方では結果が変わります
- 自動で読むツールの数字は、開発に使った 33 枚での値です（2026 年 10 月）。読ませるときに見本や正解は渡していませんが、ツールの作り（切り出し方・聞き方）はこの 33 枚を見ながら決めました
- 正解データは、Claude の書き起こしを元に作ったものです。原本で確かめた範囲は 47 か所です
- 2 回読ませて割れる・割れないの数字は、同じ写真をもう一度読ませたときの値で、呼び出しのたびに少し動きます（得点表は 25 → 26 枚）
